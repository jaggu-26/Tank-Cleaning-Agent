Breadcrumb

Overview

Breadcrumbs show the user's current location in a navigation hierarchy. They are secondary orientation aids — not primary controls — and let users jump to any ancestor level. Each item is an icon-optional link; the final item is always the current (non-interactive) page.

Anatomy

A breadcrumb is a <nav> wrapping an <ol>. Each segment is an <li> — ancestors are links, separator is an aria-hidden <li>, and the current page is a non-interactive <span>.

  1. Ancestor link — <a class="gs-bc-link">. 13px / Regular (400) / var(--color-text-muted, #94a3b8). Turns var(--color-primary, #1852fe) on hover. Displays inline-flex to accommodate optional icon with 6px gap.
  2. Separator — <li aria-hidden="true">/</li>. Forward-slash character. var(--color-border, #e2e8f0). 8px horizontal padding. Purely decorative — hidden from assistive tech.
  3. Current page — <span class="gs-bc-current" aria-current="page">. 13px / Bold (600) / var(--color-text, #10172a). Non-interactive (pointer-events:none). Bold weight distinguishes from ancestors.
  4. Icon (optional) — <svg class="gs-bc-icon"> inside the link or current span. Inherits color from parent — automatically gray (ancestor), blue (hover), or dark (current) without extra CSS.

Overview

The Breadcrumb renders a semantic <nav> + <ol> trail. Pass an array of items; the last item without an href becomes the non-interactive current page. Each item optionally accepts an icon node — the icon inherits the link's colour automatically.

JSX
{/* Without icon */}
<Breadcrumb items={[
  { label: 'Masters', href: '/masters' },
  { label: 'Masters', href: '/masters/sub' },
  { label: 'Masters' },                        // no href = current
]} />

{/* With icon */}
<Breadcrumb items={[
  { label: 'Masters', href: '/masters',     icon: <StarIcon /> },
  { label: 'Masters', href: '/masters/sub', icon: <StarIcon /> },
  { label: 'Masters',                        icon: <StarIcon /> },
]} />
HTML
<!-- Without icon -->
<gs-breadcrumb [items]="items"></gs-breadcrumb>

<!-- With icon (iconTemplate per item) -->
<gs-breadcrumb [items]="itemsWithIcon">
  <ng-template gsIcon let-item>
    <svg class="gs-bc-icon" ...></svg>
  </ng-template>
</gs-breadcrumb>

Usage Patterns
Dynamic from router
JSX
import { useMatches } from 'react-router-dom';
import { Breadcrumb } from '@pelagos/design-system';

function AppBreadcrumb() {
  const matches = useMatches();
  const items = matches
    .filter((m) => m.handle?.breadcrumb)
    .map((m) => ({
      label: m.handle.breadcrumb,
      icon:  m.handle.icon,              // optional per-route icon
      href:  m.pathname !== location.pathname ? m.pathname : undefined,
    }));
  return <Breadcrumb items={items} />;
}
TS
import { ActivatedRoute, NavigationEnd, Router } from '@angular/router';
import { filter } from 'rxjs/operators';

export class AppBreadcrumbComponent implements OnInit {
  items: BreadcrumbItem[] = [];
  constructor(private router: Router, private route: ActivatedRoute) {}
  ngOnInit() {
    this.router.events.pipe(filter(e => e instanceof NavigationEnd))
      .subscribe(() => { this.items = this.buildCrumbs(this.route.root); });
    this.items = this.buildCrumbs(this.route.root);
  }
  private buildCrumbs(route: ActivatedRoute, url='', acc: BreadcrumbItem[]=[]): BreadcrumbItem[] {
    const { data, routeConfig } = route.snapshot;
    const path = routeConfig?.path ?? '';
    const fullUrl = path ? `${url}/${path}` : url;
    if (data['breadcrumb'])
      acc.push({ label: data['breadcrumb'], icon: data['icon'], href: route.firstChild ? fullUrl : undefined });
    return route.firstChild ? this.buildCrumbs(route.firstChild, fullUrl, acc) : acc;
  }
}

When to Use
  • 3+ levels of hierarchy — When app has a clear parent–child structure (Masters → Sub-section → Detail), breadcrumbs reduce disorientation for users who land deep.
  • After deep links or search — When users arrive via notifications or external links, a breadcrumb orients them without requiring sidebar exploration.
  • Detail pages — Record-level pages (vessel profile, invoice, report detail) nested inside tables or maps — lets users return to the parent list without losing state.
  • Multi-level settings — Settings → Account → Security → 2FA. Breadcrumbs let users jump to any ancestor settings section.
  • Use the icon variant when each level has a distinct category icon (folder, chart, map, etc.) — reinforces the hierarchy visually and matches the Figma design intent.
When Not to Use
  • Flat apps (<3 levels) — "Home → Page" is redundant alongside a page title and topbar back button. Omit below 3 levels.
  • Wizards / checkout — Use instead. Breadcrumbs imply free back-navigation; steppers communicate linear progress.
  • Modals and drawers — Navigation inside overlays should be self-contained. A breadcrumb inside a modal breaks the layered context.
  • Mobile-only apps — OS back gesture covers the same need with less chrome. Reserve breadcrumbs for tablet/desktop or critical deep-link entry points.
Content Hierarchy
Label Writing Rules
  • Match the page <h1> exactly — Each breadcrumb segment mirrors the heading of the page it links to. Inconsistency confuses users clicking back.
  • Short and scannable — 1–3 words. "Reports" not "All Vessel Voyage Reports".
  • Title case — "Port Calls" not "port calls". Breadcrumbs are navigation labels, not prose.
  • Root = "Masters" (or "Home") — Use the root page's actual label, never the product or company name.
  • Icon matches label context — Use a folder icon for a list level, a document icon for a detail level. The icon variant from the Figma design uses one consistent icon per level; don't mix styles.

Common Mistakes
❌ Mistake

Making the current page label a link — clicking reloads the same page.

✅ Fix

The last item is always a non-interactive <span aria-current="page">. Remove href from the final segment. Bold weight (600) and dark color (--color-text) visually distinguish it from links.

❌ Mistake

Adding aria-hidden="true" to the icon but not to the separator — "/" gets announced by screen readers ("slash").

✅ Fix

Always set aria-hidden="true" on the separator <li>. Icons inside links also need aria-hidden since the text label already names the link.

❌ Mistake

Mixing icon variant and no-icon variant within the same breadcrumb trail — some items have icons, others don't.

✅ Fix

Consistent treatment: either every item in the trail has an icon, or none do. Mixing creates uneven visual weight and misaligned baselines.

❌ Mistake

Using <ul> instead of <ol> for the breadcrumb list.

✅ Fix

<ol> communicates ordered sequence — screen readers announce item count and position ("2 of 4"), giving users spatial context that <ul> does not.

❌ Mistake

Hardcoding breadcrumb labels instead of deriving them from route data — labels drift from page headings over time.

✅ Fix

Derive labels from route data or page metadata. Use the dynamic router pattern in the Code tab — breadcrumb labels stay in sync with page titles automatically.
