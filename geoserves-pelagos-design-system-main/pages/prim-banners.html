Banners

Overview

Pelagos provides two banner types. Info Banners (alert strips) are compact contextual messages for inline feedback — 4 semantic variants, 2 sizes, optional dismiss and action. General Banners are announcement cards with a title, description, icon, and dual-action buttons. Both dismiss smoothly using Ant Design's height-collapse animation.

Anatomy

Both banner types share the same horizontal layout: icon → body → action → close. The Info Banner uses a tinted background; the General Banner uses white with an optional circular icon.

  1. Icon — 24 × 24 px semantic SVG (Info Banner) or 42 × 42 px circle container (General Banner).
  2. Body — Flex column: bold title (SemiBold) above regular description text.
  3. Action slot — Optional. Info Banner: small ghost button. General Banner: secondary + primary button pair.
  4. Close (×) — Optional dismiss button. Triggers the 300 ms height-collapse animation.

Accessibility
Semantic roles

Info Banner uses role="alert" with aria-live="polite" so screen readers announce the message when it appears. General Banner uses role="banner".

ARIA attributes
AttributeElementValue
role="alert"Info Banner rootAnnounces to screen readers on render
aria-live="polite"Info Banner rootNon-interrupting announcement
role="banner"General Banner rootLandmark for page-level notices
aria-label="Dismiss"× close buttonLabels the icon-only button for screen readers

1
Overview

Alert is the Info Banner (strip alert). Banner is the General announcement card. Both use a shared dismiss hook implementing Ant Design's smooth height-collapse animation.

Use .gs-alert + .gs-alert--{type} + .gs-alert--{size} for alert strips. Use .gs-banner for announcement cards. Call gsBannerDismiss(btn) on the × button click.

Install / Setup
bash
npm install @pelagos/react-components

Include styles.css from the design system bundle — the .gs-alert and .gs-banner classes are globally available. Add gsBannerDismiss from script.js.

When to Use
  • Info Banner — inline feedback — Validation results, sync status, save confirmation, or permission warnings directly inside a form, panel, or table row.
  • Info Banner — non-blocking alerts — When the user needs to be informed but not interrupted. Use warning or error for actionable issues that must be resolved before proceeding.
  • General Banner — announcements — System updates, new feature launches, or policy notices that apply to the whole page and need a call-to-action button.
  • General Banner — onboarding prompts — First-run tips or guided setup steps that users should be able to dismiss after completing.
When Not to Use
  • Transient feedback — Use instead. Banners are persistent; toasts auto-dismiss.
  • Blocking confirmations — Use for destructive actions that require an explicit decision.
  • Multiple simultaneous banners — Stack a maximum of 2 Info Banners. More than that creates alert fatigue. Consider collapsing them into a single summary banner.
  • General Banner as a form header — The General Banner's 32 px vertical padding makes it too large for inside-form use. Use an Info Banner (lg) instead.
Best Practices
  • Keep messages short — Title under 6 words; description under 20 words. Long banners compete with page content.
  • Match severity to type — info for neutral tips, success for completions, warning for non-critical risks, error for failures that block the user.
  • Always provide a dismiss path — Set closable unless the banner is critical and must remain (e.g. a subscription expired error blocking a feature).
  • Action labels should be specific — "Update now" not "Click here". "Archive" not "OK".
  • Persist across navigations only when critical — General Banners for system-wide notices should persist at the page level, not per-component.
Anti-patterns
  • ❌ Using error banners for non-errors — Red is a strong signal. Using it for informational messages creates alarm without cause.
    ✅ Fix: Use info or warning type instead.
  • ❌ Omitting role="alert" — Screen readers won't announce the banner when it appears dynamically.
    ✅ Fix: Always include role="alert" + aria-live="polite" on Info Banners.
  • ❌ Non-dismissible banners with no-action path — If users cannot act on or dismiss the banner, it becomes visual noise.
    ✅ Fix: Either make it closable or link to an actionable page.
  • ❌ Using General Banner inside cards or panels — The 32 px vertical padding overflows constrained containers.
    ✅ Fix: Use Info Banner (lg) inside cards; reserve General Banner for full-width page-level notices.
