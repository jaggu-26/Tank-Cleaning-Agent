Accordion

Overview

Accordions are vertically stacked interactive headings that reveal or hide associated content panels. They reduce cognitive load by progressively disclosing information — showing only what the user requests. Pelagos accordions support single (accordion) and multi-open modes, smooth height transitions, and full keyboard navigation. Click any item below to try it.

Pelagos is a comprehensive design system for enterprise-grade GeoServes applications — providing tokens, components, and patterns for consistent, accessible interfaces at scale.

Run npm install @pelagos/react-components or @pelagos/angular-components depending on your framework.

Yes — all components target WCAG 2.1 Level AA. The accordion uses role="button", aria-expanded, and aria-controls with full keyboard support.

Anatomy

Each accordion item is a trigger header paired with a collapsible panel. The trigger is a full-width <button> for maximum tap area and keyboard operability.

  1. Container — Border: 1px --color-border-default. Radius: --radius-md. Gap between items: --prim-space-2 (6px).
  2. Header button — Full-width <button>. Heights: sm 40px · md 48px (default) · lg 56px. Padding: --prim-space-4 --prim-space-5.
  3. Chevron icon — 16×16px. Rotates 90° when open. Transition: transform 200ms ease. Colour: --prim-grey-400 (closed) → --color-brand (open).
  4. Header label — Font: --prim-font-size-md / --prim-font-weight-semibold. Colour: --prim-grey-700 (closed) → --color-brand (open).
  5. Content panel — Collapsible. Padding: --prim-space-3 --prim-space-5 --prim-space-4. No border-top by default — add via border-top: 1px solid var(--color-border-default) when a visual separator is needed.

Header Slots

Each accordion item can inject content into two zones of the header: leftExtra — non-interactive content (status badges, author, metadata) placed after the title inside the toggle zone — and rightExtra — interactive content (action buttons) placed outside the toggle button so clicks don't also collapse the panel. Clicking the title zone or the chevron still toggles the panel.

leftExtra

Placed inside the toggle button, after the title. Use for read-only metadata: status badges, timestamps, author names. Not suitable for interactive elements — the entire left zone is the toggle target.

rightExtra

Rendered outside the toggle button in a separate actions zone. Use for contextual action buttons (Add Comment, Agree, Delete). Clicks here do not collapse the panel.

Overview

Accordion wraps Ant Design's Collapse — all behaviour (keyboard, animation, aria) is delegated to AntD. Pass an items array of ItemType objects; add accordion for single-open mode. Supports controlled (activeKey) and uncontrolled (defaultActiveKey) usage. All AntD Collapse props pass through via ...rest.

Use <gs-accordion> with an [items] array — each entry configures one nz-collapse-panel via ng-zorro. Add [accordion]="true" for single-open mode. Rich panel bodies are supported via contentTemplate: TemplateRef.

Tokens

Token overrides live in accordionTheme.js. Global tokens are imported from pelagosTheme.js — never redeclared. Accordion-specific overrides only:

JS
import { globalTokens } from '../../../pelagosTheme.js';

const accordionComponentTokens = {
  headerBg:       '#ffffff',    // --prim-white / --color-surface-default
  contentBg:      '#ffffff',    // --prim-white / --color-surface-default
  contentPadding: '16px 16px',  // --prim-space-4
};

export const accordionTheme = {
  token: {
    ...globalTokens,
    colorTextHeading: '#001e4c',  // --prim-blue-900 (Figma: --primary/navy)
  },
  components: {
    Collapse: accordionComponentTokens,
  },
};

export const getAccordionTheme = () => accordionTheme;

SCSS

AntD handles all visual styling (colours, borders, backgrounds, hover/focus states) via the ConfigProvider token overrides in accordionTheme.js. The SCSS file is structural only — zero hardcoded colour values.

SCSS

// accordion__chevron--active  — expanded: rotated 180° (points up)

.accordion__chevron {
  display:     block;
  flex-shrink: 0;
  transition:  transform 200ms cubic-bezier(0.645, 0.045, 0.355, 1);
}

.accordion__chevron--active {
  transform: rotate(180deg);
}

/* ── Angular host element ─────────────────────────────────────────────── */

.gs-accordion-host {
  display: block;
}
Structural-only rule
✅ Allowed: display, flex, gap, position, overflow, z-index, cursor, transition (non-colour), transform
❌ Forbidden: color, background, border-color, box-shadow, outline-color, any hardcoded hex value

On This Page

When to Use
  • Progressive disclosure of dense content — Many sections most users don't need simultaneously; accordion hides non-critical content behind scannable headers.
  • FAQ and help pages — Users scan questions and open only what's relevant, avoiding a wall of text.
  • Settings panels grouped by category — Users jump directly to Account, Notifications, or Billing.
  • Long forms with logical sections — Reduce visual overwhelm by grouping fields into collapsible sections.
  • Sidebar filter groups — Keep filter panels compact without sacrificing accessibility.
When Not to Use
  • Equally important sections — Use instead. Accordions imply secondary content; tabs present sections as peers.
  • Only 1–2 sections — A single collapsible offers no navigation benefit. Show the content directly.
  • Cross-section comparison needed — Use a table or side-by-side layout instead.
  • Critical always-visible content — Never hide required form fields or error messages inside an accordion.
Best Practices
  • Write descriptive header labels — The header is all users see when collapsed. Labels must be self-explanatory.
  • Default-open the most important panel — Use defaultActiveKey for the panel most users need first.
  • Keep content focused per panel — Each panel should cover one coherent topic.
  • Limit nesting to one level — Accordions inside accordions create confusing interactions.
  • Consistent header typography — All headers in one accordion should use the same font size and weight (--prim-font-size-md / --prim-font-weight-semibold).
Patterns
  • FAQ Pattern — accordion mode (single-open), no default active key, equal weight across questions.
  • Settings Sections — Multi-open mode, default-open the primary section (e.g., "Profile").
  • Filter Sidebar — size="sm", multi-open so users can filter across multiple categories at once.
  • Step-by-step Form — Disable future steps until current step is valid; open next step programmatically on completion.
Anti-patterns
  • ❌ Hiding required fields — Collapsed required fields cause submission errors users can't find.
    ✅ Fix: Auto-open the section containing an error after attempted submission.
  • ❌ Nested accordions — Two-level collapse interactions are hard to keyboard-navigate.
    ✅ Fix: Flatten the hierarchy using indented list items or a tree component.
  • ❌ Vague labels — "Section 1" provides no navigation cue.
    ✅ Fix: Use specific labels: "Billing & Payments", "Notification Preferences".
  • ❌ Single-item accordion — One collapsible has no navigation benefit.
    ✅ Fix: Use a simple show/hide button or display content directly.
