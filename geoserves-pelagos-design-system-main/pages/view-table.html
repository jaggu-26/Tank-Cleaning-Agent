Overview

The GeoOne Table displays structured data with sortable columns, status badges, fuel/trade chips, and interactive row actions. It supports two modes: flat (standard row list) and stacked (grouped rows with parent-child expand/collapse). Built over the Ant Design Table spec with GeoOne tokens.

Table Header Behaviour

Sortable headers have three states: Default (grey/50 bg, label only) → Hover (grey/100 bg, search + sort buttons appear without shifting column width) → Search (TextField replaces label). Clicking the sort button cycles Default → Ascending → Descending → Default; the active direction arrow turns blue. A tooltip anchored to the sort button describes the next action.

Click the search icon to enter filter mode. The search bar fits inside the column cell (min-width 140 px). For narrow columns that can't accommodate 140 px, it expands as a floating overlay — shadow x: −8 px, y: 0, blur: 8, colour grey/400@30% — without pushing adjacent columns. Filtered columns show a blue dot indicator. Press Esc or click × to clear and close.

Overview

The GeoTable React component wraps Ant Design's Table with GeoOne design tokens applied via CSS override. Pass stackBy to enable grouped row mode. All Ant Design Table props are supported.

Use .gs-table-wrap container with semantic <table> markup. Call gsTableToggleStack(btn) for expand/collapse and gsTableMenu(btn) for 3-dot menus. All styles are in styles.css.

2
Import
JSX
import { GeoTable, StatusBadge, FuelChip } from '@pelagos/components/views/table';

Include styles.css — all .gs-table-*, .gs-cs (status chips), and .gs-ci (info chips) classes are globally available from styles.css. Call gsTableToggleStack() and gsTableMenu() from script.js.

Flat Table — Shell

Drop-in shell. Define columns to match your data shape, wire dataSource to your API response, and each row renders itself. Replace dataIndex keys and column titles as needed.

JSX
import { GeoTable, StatusBadge, FuelChip } from '@pelagos/components/views/table';

// 1. Define columns — replace keys/titles to match your data
const columns = [
  {
    title:     'Column A',     // header label
    dataIndex: 'fieldA',       // key in your data object
    sorter:    true,            // set false to disable sort
    render:    (v) => <a className="gs-td-link">{v}</a>,
  },
  {
    title:     'Column B',
    dataIndex: 'fieldB',
    sorter:    true,
  },
  {
    title:     'Column C',
    dataIndex: 'fieldC',        // plain text — no render needed
  },
  {
    title:     'Status',
    dataIndex: 'status',
    render:    (v) => <StatusBadge status={v} />,
  },
  // Add or remove columns as needed
];

// 2. Fetch data from your API
const [rows,  setRows]  = useState([]);
const [total, setTotal] = useState(0);
const [loading, setLoading] = useState(true);

useEffect(() => {
  fetchRows('/api/your-endpoint').then(({ data, count }) => {
    setRows(data);
    setTotal(count);
    setLoading(false);
  });
}, []);

// 3. Render

Lazy Loading (Infinite Scroll)

For large datasets (1,000+ rows) use IntersectionObserver on a 1 px sentinel at the table bottom. When the sentinel enters the viewport, fetch the next page and append rows. Debounce the callback by 200 ms to prevent double-fetching.

JSX
const sentinelRef = useRef(null);
const [rows, setRows]       = useState([]);
const [page, setPage]       = useState(1);
const [total, setTotal]     = useState(0);
const [loading, setLoading] = useState(false);

useEffect(() => {
  const obs = new IntersectionObserver(
    (entries) => {
      if (entries[0].isIntersecting && rows.length < total && !loading) {
        loadMore();
      }
    },
    { threshold: 0.1 }
  );
  if (sentinelRef.current) obs.observe(sentinelRef.current);
  return () => obs.disconnect();
}, [rows.length, total, loading]);

const loadMore = debounce(async () => {
  setLoading(true);
  const { data, count } = await fetchRows({ page: page + 1 });
  setRows(prev => [...prev, ...data]);
  setTotal(count);
  setPage(p => p + 1);
  setLoading(false);
}, 200);  // 200ms debounce prevents double-fetch

// Render sentinel below GeoTable
<GeoTable columns={columns} dataSource={rows} loading={loading} />
<div ref={sentinelRef} style={{ height: 1 }} />  // 1px sentinel
JS
// Wire IntersectionObserver to the sentinel element
const sentinel = document.getElementById('tbl-lazy-sentinel');
let   page = 1, total = 0, loading = false;

const observer = new IntersectionObserver((entries) => {
  if (!entries[0].isIntersecting || loading) return;
  loadNextPage();
}, { threshold: 0.1 });
observer.observe(sentinel);

function loadNextPage() {
  loading = true;
  sentinel.style.display = 'flex';    // show spinner

  fetch(`/api/rows?page=${page + 1}`)
    .then(r => r.json())
    .then(({ data, count }) => {
      appendRows(data);               // append tr elements to tbody
      total = count;
      page++;
      sentinel.style.display = 'none';
      loading = false;
      if (page * 20 >= total) observer.disconnect();  // all loaded
    });
}

//   <div class="tbl-lazy-spinner"></div> Loading more records…

On This Page

When to Use
  • Large structured datasets — vessel inquiry lists, contract ledgers, invoice registers where users need to scan, sort, and filter many rows.
  • Stacked mode — when multiple voyages or stems share a vessel, or when contract rows have child stem dates. Groups related rows under a collapsible parent.
  • Action-heavy rows — use the 3-dot column when rows have multiple context-sensitive actions (Raise Claim, View Details, Export).
  • Status-driven workflows — when row colour-coding and badge states communicate progress across a workflow pipeline.
When Not to Use
  • Simple key-value display — use a Description List for detail panels; the table adds unnecessary visual weight.
  • Fewer than 5 rows with no sorting need — a plain list or card layout is lighter and more scannable.
  • More than 3 levels of hierarchy — stacked mode only supports parent → children (1 level deep). Deeper nesting needs a dedicated tree component.
Best Practices
  • Freeze the Job No / Vessel column when the table has 8+ columns so users retain row context while scrolling horizontally.
  • Show Days to Claim only on Delivered tab — this column is tab-conditional and shouldn't appear on All, Active, or Booked views.
  • Use fuel chip tooltips for multi-fuel rows — never try to display all fuel grades inline; the tooltip pattern keeps cell width consistent.
  • Set rowKey to a stable unique ID — never use array index as the key; it breaks selection and animation state on sort/filter.
  • Limit visible columns to ~8–10 — prefer tab-based column sets (All, Active, Delivered) over one mega-table with all columns.
Anti-patterns
  • ❌ Colour-only status — never rely solely on badge colour; always include a text label for colour-blind users.
    ✅ Fix: every .gs-cs / .gs-ci chip always has visible text.
  • ❌ Truncating all cells — over-truncation hides context. Only truncate long free-text fields (Buying Entity, Seller).
    ✅ Fix: .gs-td-trunc class with max-width, never applied globally.
  • ❌ Stacking without an aggregation strategy — showing blank parent cells is confusing. Plan what the parent row summarises (port count, commodity count, etc.).
    ✅ Fix: parent cells always show either aggregated data or a clear tally (2 Ports, 1 counterparty).
