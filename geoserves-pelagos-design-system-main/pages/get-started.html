Get Started

Designers use Claude desktop (Cowork mode) — no terminal required. Claude reads and edits component files directly, previews in the browser, then commits and pushes to GitHub for you.
1 · Setup Claude with the design system

Connect Claude to the repository once. After that, every design task — updating components, adding Figma designs, rebuilding the preview — is a single conversation.

1

Install Claude desktop

Download the Claude desktop app from claude.ai/download. Sign in with your Anthropic account. Cowork mode is enabled by default.

2

Open the design system folder

In Claude, click the folder icon or type + and select Choose workspace folder. Navigate to the cloned pelagos-design-system folder and confirm. Claude now has read/write access to all component files.

If you haven't cloned the repo yet, ask Claude: "Clone the Pelagos design system from GitHub: [repo-url]" — it will handle Git setup for you.
3

Start the preview server

Tell Claude to start the local server. It runs automatically, but if you need to restart:

# Claude will run this for you — just ask it to "start the server" node .claude/serve.js

Then open http://localhost:3456 in your browser to preview all changes live.

4

Configure Git identity (one-time)

Ask Claude to configure your Git identity so commits show your name:

# Tell Claude: "Set up my Git identity" git config --global user.name "Your Name" git config --global user.email "you@geoserves.com"
2 · Daily workflow

Every change follows the same loop — pull latest → describe what you want → review in browser → push. Claude handles everything in between.

1

Always pull before starting work

Ask Claude to pull the latest changes so you're never working on stale files.

Say to Claude
"Pull the latest changes from the main branch before we start."
2

Describe your task

Tell Claude exactly what you want to change. The more specific you are, the better the result. You can reference Figma URLs, paste screenshots, or point to existing components.

Update from Figma
"Implement this design from Figma: @https://figma.com/design/TOLfBpRePgynqwvDVp6fg3/...?node-id=… — update the Accordion component to match the hover and expanded states."
Fix a specific state
"The hover state on the Popover is not working when the panel is open. Fix it — hover should show blue/10 (#eef6ff) in both collapsed and expanded states."
Add a new component
"Use the HOW_TO_ADD_COMPONENT.md guidelines to add a new Tooltip component page with Design, Code, and Usage tabs. Use our existing gs-btn and gs-popover classes in previews."
Bulk update
"Add an 'On This Page' quick-nav sidebar to the Buttons, Text Fields, and Toasts pages — all tabs."
3

Review in the browser

Claude rebuilds the bundle automatically after each change. Refresh localhost:3456 and navigate to the component you updated. If something looks wrong, describe the issue and Claude will fix it.

If the browser shows old content, ask Claude: "Rebuild the bundle". It runs python3 rebuild-bundle.py which repacks all page HTML into bundle.js.
4

Commit and push

When you're happy with the changes, ask Claude to commit and push.

Say to Claude
"Looks good. Commit these changes with the message: feat(accordion): add Carbon animation + fix hover/expanded states and push to main."
# Claude runs this sequence for you git add . git commit -m "feat(accordion): add Carbon animation + fix hover/expanded states" git push origin main
3 · Working with Figma

Claude can read Figma designs directly from a URL. Paste the dev-mode link and Claude extracts colours, spacing, fonts, and component structure automatically.

1

Get the Figma dev-mode URL

In Figma, right-click a frame → Copy link. The URL should contain a node-id parameter. Share this URL directly in your Claude message.

# Example Figma URL format https://figma.com/design/TOLfBpRePgynqwvDVp6fg3/Design-System?node-id=12983-50855
2

Reference it in your prompt

Use the @url syntax or just paste the URL inline. Claude fetches the design context, screenshots, and token values.

Example prompt
"Implement this design from Figma — use the illustrations from Assets/illustrations/ for the confirmation modal variants: @https://figma.com/design/TOLfBpRePgynqwvDVp6fg3/Design-System?node-id=11463-3626"
3

Specify context for better results

Tell Claude which framework, which file to update, and any constraints.

Effective Figma prompt
"Implement this from Figma [URL]. Update panel-popover.html. Use gs-btn gs-btn-secondary gs-btn-sm for triggers, gs-pop-item for menu rows. Min-width 200px. Show both on-click and on-hover scenarios."
4 · Prompting tips for best results

Claude works best when you give it specific constraints and reference the existing system. These patterns get consistent, high-quality output.

📎
Reference the MD files
The system has HOW_TO_ADD_COMPONENT.md, DS_STRUCTURE_CODE.md, and others. Tell Claude to follow them: "Use the HOW_TO_ADD_COMPONENT.md spec."
🎯
Be specific about scope
Instead of "fix the modal", say "fix the expanded state hover on the accordion header — should be blue/10 not brand-subtle." Narrow scope = fewer mistakes.
🔁
Iterate in the browser
After each change, check the browser and describe what's still off. Claude sees the code — describe the visual problem and it traces back the CSS cause.
📸
Paste screenshots
Claude can see images. Paste a screenshot of the Figma design or a browser screenshot of what's wrong. Combined with "Fix this" it's very accurate.
🧩
Use existing classes
Say "use gs-btn gs-btn-primary for the trigger" instead of custom markup. Consistency keeps the system coherent across all component demos.
🔒
Always rebuild + commit
Changes to HTML pages don't show until the bundle is rebuilt. Ask Claude: "Rebuild the bundle and commit." It does both in one step.
Git commit message conventions
# Use conventional commits — Claude follows this format if you ask feat(component): add new feature fix(component): fix a bug or visual issue chore: rebuild bundle, update docs style(component): CSS-only change, no logic refactor: restructure without changing behaviour # Example git commit -m "feat(popover): add Carbon animation + sliding pill for segmented button"
5 · Git quick reference

Ask Claude to run any of these. You never need to open a terminal.

# Pull latest before starting work git pull origin main # Check what changed git status git diff # Stage, commit, and push in one go git add . git commit -m "your message" git push origin main # Create a branch for experimental work git checkout -b feat/new-component # Rebuild the bundle after any HTML page edit python3 rebuild-bundle.py

On This Page

After each design system update the changes are pushed to GitHub. Pull the latest changes and re-import the stylesheet to pick up new tokens or component patterns.
1 · Get the source

Clone the repository or add it as a git dependency. GitHub links will be provided once the repository is published.

# Clone the repository git clone https://github.com/your-org/pelagos-design-system.git # Or add as a git dependency in package.json "@geoserve/pelagos": "github:your-org/pelagos-design-system" # Install npm install
2 · Import the token stylesheet

Include tokens.css once at your application root. This registers all CSS custom properties globally — colours, spacing, radius, shadows, and typography. See Design Tokens for the full reference.

/* In your global CSS entry (e.g. index.css or App.css) */ @import './pelagos-design-system/dist/tokens.css'; /* Or in your JS entry point (React, Vue, Angular…) */ import '@geoserve/pelagos/dist/tokens.css';
3 · Use tokens in your styles

Reference CSS custom properties in stylesheets, inline styles, or CSS-in-JS. Token names follow a three-tier hierarchy: --prim-* → --color-* → --btn-*. Always reference the highest applicable tier.

.vessel-card { background: var(--color-surface-default); border: 1px solid var(--color-border-default); border-radius: var(--radius-lg); /* 16px */ padding: var(--prim-space-5) var(--prim-space-6); /* 20px 24px */ box-shadow: var(--shadow-md); } .status-active { color: var(--color-success); background: var(--color-success-subtle); }
4 · Copy component patterns

Every component ships with production-ready HTML. Browse the Components section, pick a pattern, and paste it into your project. All class names are prefixed gs-.

<!-- Primary button --> <button class="gs-btn gs-btn-primary gs-btn-md">Save changes</button> <!-- Text field --> <div class="gs-tf-box"> <label class="gs-tf-label">Voyage ID</label> <input class="gs-tf-input" placeholder="VOY-2025-001" /> </div> <!-- Popover action menu --> <div class="gs-pop-wrap"> <button class="gs-btn gs-btn-secondary gs-btn-sm" id="my-t" aria-haspopup="menu" aria-expanded="false" onclick="gsPopoverToggle('my-t','my-p')">Actions</button> <div class="gs-popover gs-popover--bottom-start" id="my-p" role="menu"> <button class="gs-pop-item" role="menuitem">Edit</button> <button class="gs-pop-item gs-pop-item--danger" role="menuitem">Delete</button> </div> </div>
5 · React components

All components have a React counterpart in components/. Import and use them directly — they accept the same design token system.

import { Modal, ConfirmModal } from '@pelagos/components/panels/modal'; import { Popover, PopoverItem, PopoverDivider, PopoverToggleRow } from '@pelagos/components/panels/popover'; import { Accordion } from '@pelagos/components/primitives/accordion'; import { Toggle } from '@pelagos/components/primitives/toggle'; // Delete confirmation modal <ConfirmModal open={showDelete} onClose={() => setShowDelete(false)} onConfirm={handleDelete} variant="delete" title="Delete Port call" message="Are you sure you want to delete (HHTX-202411)?" /> // Action popover <Popover placement="bottom" trigger="click" content={ <> <PopoverItem icon={<EditIcon />} label="Edit Details" onClick={onEdit} /> <PopoverDivider /> <PopoverItem icon={<TrashIcon />} label="Delete" danger onClick={onDelete} /> </> }> <button className="gs-btn gs-btn-secondary gs-btn-sm">Actions</button> </Popover>
6 · Stay up to date

Pull the latest changes and re-import. Your existing components automatically inherit updated token values — no code changes needed if you're using the CSS custom properties.

# Pull latest from main git pull origin main # If installed as an npm git dependency npm update @geoserve/pelagos # Check the changelog for breaking changes cat CHANGELOG.md | head -50
If you override component CSS, check the Design Tokens page after each update — token names occasionally change between minor versions during the pre-1.0 phase.
