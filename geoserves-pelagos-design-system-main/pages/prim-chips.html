Chips

Overview

Chips are small visual elements that communicate an attribute, category, or action in a constrained space. The design system provides four chip types, each with a distinct purpose.

Chip Info

Color-coded label chips in Filled, Outlined, and Light variants across six colors.

Person/input chips with avatar, label, and remove action. Used in multi-select fields.

Chip Interactive

Clickable filter chips with Default, Hover, Selected, Disabled, and Focused states.

Chip Interactive

Filter/selection chips. Always render as <button>. Toggle is-selected on click. Use aria-pressed to communicate selection state. Add has-icon when using left icon.

JSX — Interactive single
function FilterChip({ label, color = 'blue', selected, disabled, icon, onClick }) {
  return (
    <button
      type="button"
      className={[
        'gs-cia',
        `gs-cia--${color}`,
        icon ? 'has-icon' : '',
        selected ? 'is-selected' : '',
        disabled ? 'is-disabled' : '',
      ].filter(Boolean).join(' ')}
      aria-pressed={selected}
      disabled={disabled}
      onClick={onClick}
    >
      {icon && (
        <span className="gs-cia__icon" aria-hidden="true">
          <svg viewBox="0 0 24 24" fill="none" stroke="currentColor"
               strokeWidth="2.5" strokeLinecap="round" strokeLinejoin="round">
            <path d="M20 6L9 17l-5-5"/>
          </svg>
        </span>
      )}
      <span className="gs-cia__label">{label}</span>
    </button>
  );
}

JSX — Filter chip group (multi-select)
const FILTERS = [
  { id: 'active',   label: 'Active',   color: 'blue'  },
  { id: 'pending',  label: 'Pending',  color: 'yellow' },
  { id: 'failed',   label: 'Failed',   color: 'red'   },
  { id: 'archived', label: 'Archived', color: 'grey'  },
];

function FilterGroup() {
  const [selected, setSelected] = useState(new Set());
  const toggle = (id) => setSelected(prev => {
    const next = new Set(prev);
    next.has(id) ? next.delete(id) : next.add(id);
    return next;
  });
  return (
    <div style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }} role="group" aria-label="Filter by status">
      {FILTERS.map(f => (
        <button
          key={f.id}
          type="button"
          className={`gs-cia gs-cia--${f.color}${selected.has(f.id) ? ' is-selected' : ''}`}
          aria-pressed={selected.has(f.id)}
          onClick={() => toggle(f.id)}
        >
          {f.label}
        </button>
      ))}
    </div>
  );
}

function AccessibleFilterGroup({ label, filters, selected, onChange }) {
  return (
    <div
      role="group"
      aria-label={label}
      style={{ display: 'flex', gap: 8, flexWrap: 'wrap' }}
    >
      {filters.map((f) => {
        const isSelected = selected.has(f.id);
        return (
          <button
            key={f.id}
            type="button"
            className={`gs-cia gs-cia--${f.color}${isSelected ? ' is-selected' : ''}`}
            aria-pressed={isSelected}
            onClick={() => onChange(f.id)}
          >
            {f.label}
          </button>
        );
      })}
    </div>
  );
}

Usage

Guidelines for selecting the right chip type, structuring content, and avoiding common implementation mistakes.

Choosing the right chip type
TypeUse whenDo not use when
Chip Info Displaying a category, tag, or attribute alongside content (e.g., in a card header, table cell, or detail panel). Conveying live operational status — use Chip Status. The user needs to click it — use Chip Interactive.
Chip Status Communicating the current operational state of a record (Active, Pending, Failed, etc.) in tables, sidebars, and record headers. Decorative labels with no semantic meaning. Do not use status chips for categories or tags.
BWBruce Representing selected people, assigned users, or input tokens inside a multi-select field. Static display of names — use plain text or a badge. Do not show Chip Field outside an input context.
Filter bars, faceted search, tag selection, or any UI where the user toggles a filter/option on and off. Status display — use Chip Status. One-time navigation actions — use a button or a link.
When to use
✓ Do
  • Use Chip Info to annotate content with metadata (e.g., "New", "Beta", priority level).
  • Use Chip Status in table rows and record headers where status changes over time.
  • Use Chip Field inside search and assignment inputs where users pick multiple people or items.
  • Use Chip Interactive in filter toolbars to let users narrow down results — show clearly which filters are selected.
  • Keep chip labels concise: 1–3 words maximum.
  • Use the Outlined variant of Chip Interactive when the chip appears on a coloured or image background.
✗ Don't
  • Don't use multiple chip types together in the same element (e.g., mixing Chip Info and Chip Status side by side to mean the same thing).
  • Don't make Chip Info or Chip Status clickable — if action is needed, use Chip Interactive instead.
  • Don't rely on color alone to convey status — the label text must also be descriptive (e.g., "Active" not just a green chip).
  • Don't truncate chip labels — if the text is too long, reconsider the label or use a tooltip.
  • Don't use chips as navigation elements — use links or tabs instead.
  • Don't use more than 3 chip colors in a single view — too many colors reduce semantic meaning.
Content guidelines
RuleGuidance
Label length1–3 words preferred. Maximum 20 characters before the chip becomes unwieldy in dense layouts. Long labels should be truncated only as a last resort, with full text accessible via tooltip.
CapitalisationTitle case for status values (e.g., "In Progress"). Sentence case or all-lowercase for tags/categories (e.g., "design", "backend").
Chip Info vs BadgeUse Chip Info for inline categorical labels next to content. Use the Badge component for notification counts on icons and navigation items.
Numbers in chipsAcceptable in Chip Info (e.g., version numbers, counts). Avoid in Chip Status and Chip Interactive — use numeric values sparingly.
Avatar initialsUse first + last initial (e.g., "BW" for Bruce Wayne). Single initial only when last name is unavailable. Never show more than 2 characters.
Chip Interactive labelMatch exactly to the filter value being represented — avoid abbreviations. "Marketing" not "Mktg".
Common mistakes
MistakeProblemFix
Using <div> or <span> for Chip Interactive Not keyboard accessible. Screen readers won't announce it as interactive. Always use <button type="button"> with aria-pressed.
Missing aria-label on close button "Remove" alone gives no context. Screen reader users can't tell which chip will be removed. Use aria-label="Remove [person name]" — include the chip content in the label.
Applying is-selected without updating aria-pressed Visual state changes but screen readers don't announce the selection change. Dynamically toggle aria-pressed="true/false" alongside the is-selected class.
Using Chip Status for all label use-cases Overloads the semantic meaning of status colors — "Red" begins to mean different things. Reserve Chip Status strictly for operational states. Use Chip Info for categories and tags.
Overriding chip text color without checking contrast Custom color combinations may fail WCAG 2.1 AA (4.5:1 minimum). Only use the system-provided color combinations. If customization is needed, verify contrast with a tool.
Stacking chips vertically instead of wrapping Vertical chip lists waste horizontal space and break visual scannability. Use display: flex; flex-wrap: wrap; gap: 8px on the chip container.
Accessibility checklist
Interactive chips use <button type="button"> — never <div> or <span>. Buttons receive keyboard focus and fire on Enter/Space natively.
aria-pressed kept in sync with the is-selected class at all times so screen readers announce selection changes.
Chip Field close button has aria-label="Remove [name]" so users know which item will be removed.
Disabled chips use the native disabled attribute (not just the .is-disabled class) so assistive technology skips the element in tab order.
Chip Interactive groups are wrapped in role="group" with aria-label (e.g., "Filter by status") so screen readers announce group context before individual chips.
Chip Status in live regions: add role="status" and ensure a parent has aria-live="polite" when status values update dynamically.
Color contrast: do not override text colors without verifying ≥4.5:1 contrast (WCAG AA). All built-in color combinations are pre-verified.
Focus ring: do not suppress :focus-visible — the 1.5px brand-color ring is required for keyboard users. Adding outline:none without a replacement fails WCAG 2.4.7.
Related components
Badge

Use for notification counts on icons and nav items. Badges are non-interactive and position-absolute over their parent. Do not use chips as badges.

Toggle

Use when a single on/off setting takes immediate effect. Toggles communicate a binary live state, whereas Chip Interactive is for selecting among a group of options.

Dropdown

Use when the option list has more than 7 items, requires search, or needs a hierarchical structure. Chips work best for 2–7 visible, flat options.

Text Field

Chip Field lives inside text fields for multi-select person/item input. Understanding the text field component helps with correct layout and focus management.
