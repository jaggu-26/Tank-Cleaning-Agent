Modals

Modals interrupt the user's workflow to present critical information or to request a decision. The system provides two main types: Default modals for data entry and complex tasks, and Confirmation modals for destructive or high-stakes decisions.

Anatomy

Every modal is structured around four zones: Header, Panel (optional), Content, and Footer. The Panel zone sits between the header and content — it's purpose-built for tabs, alerts, or contextual info strips without polluting the header or content areas.

The modal always renders Header → Panel (if provided) → Content → Footer in that order. This keeps navigation context (Panel) visually separate from task content.

  1. Header: Modal title + close ×. Fixed height, never scrolls. Separated from the next zone by a 1px divider.
  2. Panel optional: Secondary navigation or contextual info. Accepts any ReactNode — tab strips, alert banners, breadcrumbs, or info rows. Omit the prop and the zone is not rendered.
  3. Content: The scrollable task area — forms, data tables, review text. Gets overflow-y: auto automatically.
  4. Footer: Right-aligned action buttons. Primary action always rightmost. Confirmation variants switch to a stacked column layout.
  5. Close ×: Dismisses the modal without submitting. Always present in the header's trailing slot.
  6. Overlay: Gray-800 at 70% opacity backdrop. Clicking it also closes the modal.

On This Page

The Modal component wraps Ant Design's Modal with a Geoserve className so all visual overrides live in Modal.scss. Styles are written as SCSS variables that bridge CSS custom properties, keeping every value traceable back to the foundational token chain: $modal-* → var(--modal-*) → var(--color-*) → var(--prim-*) → raw value.

theme/gs-theme.js

JavaScript · Geoserve Theme 
/**
 * Geoserve UI theme config — injected via <ConfigProvider theme={gsTheme}>.
 *
 * Token values are read from the design-system CSS custom properties at
 * runtime via getComputedStyle so any update to :root cascades here
 * automatically — no hard-coded hex values in this file.
 *
 * Token chain example:
 *   borderRadiusLG  ←  --modal-radius-md  ←  :root { --modal-radius-md: 16px }
 */
const cssVar = (name) =>
  getComputedStyle(document.documentElement).getPropertyValue(name).trim();

const gsTheme = {
  token: {
    colorPrimary:    cssVar('--prim-marine'),       // → #1852FE
    colorError:      cssVar('--prim-red-500'),      // → #DC2625
    fontFamily:      cssVar('--prim-font-primary'),  // Gilroy stack
    fontSize:        14,
    borderRadius:    4,
  },
  components: {
    Modal: {
      borderRadiusLG:              16,   // --modal-radius-md → default modal
      paddingMD:                   16,   // --modal-padding → header / footer
      paddingContentHorizontalLG:  16,   // --modal-padding → body
      paddingContentVerticalLG:    16,
      titleFontSize:               16,   // --modal-title-size
      titleLineHeight:             1.4,
      headerBg:                    '#ffffff',
      contentBg:                   '#ffffff',
      footerBg:                    '#ffffff',
    },
  },
};

export default gsTheme;

useModal.js

JavaScript · React Hook 
import { useState, useCallback } from 'react';

/**
 * Manages Ant Design Modal open state.
 * antd Modal handles Escape key and animation natively,
 * so this hook only needs to expose open / close.
 *
 * @returns {{ open: boolean, handleOpen: () => void, handleClose: () => void }}
 */
export function useModal() {
  const [open, setOpen] = useState(false);

  const handleOpen  = useCallback(() => setOpen(true),  []);
  const handleClose = useCallback(() => setOpen(false), []);

  return { open, handleOpen, handleClose };
}

Modal/Modal.jsx

JavaScript · React 
import React from 'react';
import { Modal as AntModal } from 'antd';
import './Modal.scss';

/**
 * Maps GS size shorthand → Ant Design modal width.
 * Border-radius is handled in Modal.scss via the --sm / --lg modifier class.
 */
const WIDTH_MAP = {
  sm: 400,
  md: 560,
  lg: 800,
};

/**
 * Four-zone layout: Header → Panel (optional) → Content → Footer.
 *
 * @param {object}    props
 * @param {boolean}   props.open        - controls visibility (from useModal)
 * @param {function}  props.onClose     - called when user closes (from useModal.handleClose)
 * @param {string}    props.title       - header title text
 * @param {ReactNode} [props.panel]     - optional panel zone: tabs, alerts, context rows
 * @param {'sm'|'md'|'lg'} [props.size='md']
 * @param {boolean}   [props.confirm]   - confirmation variant (centred + stacked footer)
 * @param {ReactNode} props.children    - content slot (scrollable body)
 * @param {ReactNode} [props.footer]    - footer slot; pass null to hide footer
 * @param {string}    [props.className] - additional CSS classes
 */
export function Modal({
  open,
  onClose,
  title,
  panel,
  size      = 'md',
  confirm   = false,
  children,
  footer,
  className = '',
}) {
  const cls = [
    'gs-modal',
    size !== 'md' && `gs-modal--${size}`,
    confirm && 'gs-modal--confirm',
    panel && 'gs-modal--has-panel',
    className,
  ].filter(Boolean).join(' ');

  return (
    <AntModal
      open={open}
      onCancel={onClose}
      title={title}
      footer={footer ?? null}
      width={WIDTH_MAP[size]}
      className={cls}
      classNames={{ mask: 'gs-modal-mask' }}
      styles={{ body: panel ? { padding: 0 } : undefined }}
      centered
      destroyOnClose
      closeIcon={
        <svg width="16" height="16" viewBox="0 0 24 24" fill="none"
             stroke="currentColor" strokeWidth="2" strokeLinecap="round">
          <path d="M18 6 6 18M6 6l12 12" />
        </svg>
      }
    >
      {panel && <div className="gs-modal__panel">{panel}</div>}
      {panel
        ? <div className="gs-modal__content">{children}</div>
        : children}
    </AntModal>
  );
}

import { useState }        from 'react';
import { Modal, useModal } from '@/components/Modal';
import { Button }         from '@/components/Button';

// Reusable tab strip — lives in gs-modal__panel zone
function ModalTabs({ tabs, active, onChange }) {
  return (
    <div className="gs-modal__tabs">
      {tabs.map(t => (
        <button
          key={t.key}
          className={`gs-modal__tab${active === t.key ? ' gs-modal__tab--active' : ''}`}
          onClick={() => onChange(t.key)}
        >
          {t.label}
        </button>
      ))}
    </div>
  );
}

function AddUserModal() {
  const { open, handleOpen, handleClose } = useModal();
  const [tab, setTab] = useState('details');

  const tabs = [
    { key: 'details',     label: 'Details'     },
    { key: 'permissions', label: 'Permissions' },
    { key: 'history',     label: 'History'     },
  ];

  return (
    <>
      <Button variant="primary" onClick={handleOpen}>Add User</Button>

      <Modal
        open={open}
        onClose={handleClose}
        title="Add User"
        panel={<ModalTabs tabs={tabs} active={tab} onChange={setTab} />}
        footer={
          <>
            <Button variant="secondary" onClick={handleClose}>Cancel</Button>
            <Button variant="primary"   onClick={handleSubmit}>Save User</Button>
          </>
        }
      >
        {tab === 'details'     && <UserDetailsForm />}
        {tab === 'permissions' && <PermissionsPanel />}
        {tab === 'history'     && <ActivityLog />}
      </Modal>
    </>
  );
}

            <Button variant="secondary" onClick={handleClose}>Cancel</Button>
          </>
        }
      >
        <p>This will permanently remove the vessel and all associated data.</p>
      </Modal>
    </>
  );
}

modal/modal.component.ts

TypeScript · Angular
import {
  Component, Input, Output, EventEmitter, HostListener
} from '@angular/core';
import { CommonModule } from '@angular/common';

export type ModalVariant = 'default' | 'danger' | 'success' | 'warning';
export type ModalSize    = 'sm' | 'md' | 'lg' | 'xl';

@Component({
  selector: 'gs-modal',
  standalone: true,
  imports: [CommonModule],
  templateUrl: './modal.component.html',
  styleUrls: ['./modal.component.scss'],
})
export class ModalComponent {
  @Input() open    = false;
  @Input() title   = '';
  @Input() variant: ModalVariant = 'default';
  @Input() size:    ModalSize    = 'md';
  @Input() closable = true;
  @Output() closed    = new EventEmitter<void>();
  @Output() confirmed = new EventEmitter<void>();

  @HostListener('keydown.escape')
  onEscape(): void { this.close(); }

  close(): void   { if (this.closable) this.closed.emit(); }
  confirm(): void { this.confirmed.emit(); }

  onOverlayClick(e: MouseEvent): void {
    if ((e.target as HTMLElement).classList.contains('gs-modal__overlay')) {
      this.close();
    }
  }
}

Modals are high-friction UI. They block the user's current task and demand immediate attention. Use them deliberately — only when the task cannot be completed inline or on a separate page.

Dos & Don'ts

Do

  • Use modals only when the user must respond before continuing
  • Always provide a clear dismissal path — × button, Cancel, overlay click, and Escape key
  • Keep modal content focused — move complex workflows to a dedicated page
  • Use action-specific button labels — "Delete Record" not "OK"
  • Always show a confirmation modal before any destructive action executes
  • Trap focus inside the modal and return focus to the trigger on close
  • Lock body scroll when a modal is open to prevent scroll bleed

Don't

  • Don't open a modal from within a modal
  • Don't use modals for non-critical info that belongs in a tooltip or inline callout
  • Don't make modals non-dismissible unless the task is truly mandatory
  • Don't use vague labels like "Yes", "No", or "OK"
  • Don't auto-trigger a modal on page load
  • Don't put lengthy scroll-heavy content in a modal — use a drawer or separate page
  • Don't stack multiple primary actions in the footer

Accessibility

WCAG 2.1 AA Checklist

Use role="dialog" and aria-modal="true" on the dialog. Link the title via aria-labelledby.
Focus trap — keyboard focus must stay inside the modal. Move focus to the first interactive element on open.
Escape key closes the modal. The × button must have aria-label="Close modal".
Focus return — on close, focus must return to the trigger element that opened the modal.
Background inert — mark the rest of the page with inert or aria-hidden="true" while the modal is open.
Contrast — all text inside the modal must meet 4.5:1 contrast ratio (WCAG AA).
Reduced motion — honour prefers-reduced-motion. Disable scale + fade animation when active.
Scroll lock — prevent body scroll via overflow: hidden while the modal is open. Restore on close.

Alignment

Centred (default)

Modals are always centred horizontally and vertically in the viewport using the centered Ant Design prop. This provides a clear focal point and prevents the modal from feeling anchored to a specific page element.

48px safe zone

The modal container enforces a minimum 48px margin from all viewport edges. This guarantees the modal card never bleeds to the edge on smaller viewports and keeps the overlay visible as a contextual dimmed background.

Footer actions — right-aligned

Default modal footer buttons are right-aligned. The primary action is always the rightmost button. Confirmation modal buttons are stacked full-width (primary on top) to make the intent unmistakable and reduce mis-taps on destructive actions.

Sizing

Small 400px

Confirmations, single-action prompts, simple alerts. No complex content. Centred illustration + text + 1–2 stacked buttons.

Medium default 560px

Standard forms, settings panels, user management, invite flows. Supports a panel zone for tab navigation. 2-column form grid.

Large 800px

Data review, document previews, multi-step flows with rich content. Increased padding (24px). Use sparingly — prefer a drawer or full page for deeply complex tasks.

Rule: Never size a modal wider than the viewport minus 96px (48px × 2). The 48px safe zone is non-negotiable.

Universal Behaviours

Esc Close

Pressing Escape always closes the modal. Disable only when the modal represents a mandatory step with no cancel path (very rare — always warn the user).

Overlay click — close

Clicking the overlay dismisses the modal for default forms. Set maskClosable={false} for destructive confirmations so the user must explicitly choose an action.

Focus trap

Keyboard focus is trapped inside the modal while open. Tab and Shift+Tab cycle through interactive elements only within the modal. Focus moves to the first interactive element on open.

Scroll lock

Body scroll is locked (overflow:hidden) while a modal is open to prevent scroll bleed through to the page behind. Restored on close.

One modal at a time

Never open a modal from within a modal. If a confirmation is needed inside a form modal, close the form first, confirm, then re-open if required. Nesting modals creates disorienting z-index stacks.

Focus return

On close, focus must return to the element that triggered the modal (e.g. the "Add User" button). Ant Design handles this automatically via destroyOnClose.

Loading State

When a modal needs to fetch data before displaying content, show a skeleton screen — never a spinner alone. The skeleton preserves the layout structure so the interface feels stable and predictable.
