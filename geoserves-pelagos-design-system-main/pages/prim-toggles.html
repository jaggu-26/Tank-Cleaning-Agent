Switch

Overview

Toggles and switches are binary controls that instantly apply a setting without requiring a submit action. They replace checkboxes when a setting takes immediate effect — enabling dark mode, turning notifications on. Pelagos provides three sizes and a loading state, with smooth thumb-slide transitions and complete ARIA switch semantics.

Anatomy

A switch is a single <button role="switch"> element. It consists of a pill-shaped track and a circular thumb that slides between off (left) and on (right). An optional label sits beside it.

  1. Label — Optional. Font: --prim-font-size-md / --prim-font-weight-medium. Gap to track: --prim-space-3 (12px). Colour: --color-text-secondary (off) → --color-text-default (on).
  2. Track — Pill background. Sizes: sm 36×20px, md 44×24px (default), lg 52×28px. Colour: --prim-grey-100 (off) → --color-brand (on). Radius: --radius-full.
  3. Thumb — White circle with --prim-shadow-sm. Diameter: sm 16px, md 20px, lg 24px. 2px inset from track edge. Slide transition: transform 200ms ease.

Semantic Element

The switch renders as <button role="switch"> — not <input type="checkbox"> — because it represents an immediate-effect binary state, not a submitted form value. aria-checked mirrors the current state.

Overview

The Switch component renders button[role="switch"]. Supports controlled and uncontrolled usage, async loading state, and optional label. Returning a Promise from onChange activates the loading spinner automatically.

Use <gs-switch> with [(ngModel)] for two-way binding, or [checked] + (checkedChange) for controlled usage.

JSX
const [checked, setChecked] = useState(false);
const [loading, setLoading] = useState(false);

async function handleToggle(val: boolean) {
  setLoading(true);
  try { await api.save(val); setChecked(val); }
  finally { setLoading(false); }
}

<Switch
  checked={checked}
  loading={loading}
  onChange={handleToggle}
  aria-label="Email notifications"
/>
TS
checked = false; loading = false;
async onToggle(val: boolean) {
  this.loading = true;
  await this.api.save(val);
  this.checked = val; this.loading = false;
}

Full Example
JSX
import { useState } from 'react';
import { Switch } from '@pelagos/react-components';

export function SettingsPanel() {
  const [prefs, setPrefs] = useState({
    notifications: true, darkMode: false, analytics: true
  });
  const toggle = (key) => setPrefs(p => ({ ...p, [key]: !p[key] }));

  return (
    <div style={{ display:'flex', flexDirection:'column', gap:'var(--prim-space-5)' }}>
      {[
        ['notifications', 'Email notifications'],
        ['darkMode',      'Dark mode'],
        ['analytics',    'Analytics'],
      ].map(([k, lbl]) => (
        <div key={k} style={{ display:'flex', justifyContent:'space-between', alignItems:'center' }}>
          <label id={`lbl-${k}`}
            style={{ fontFamily:'var(--prim-font-primary)', fontSize:'var(--prim-font-size-md)' }}
          >{lbl}</label>
          <Switch
            checked={prefs[k]}
            onChange={() => toggle(k)}
            aria-labelledby={`lbl-${k}`}
          />
        </div>
      ))}
    </div>
  );
}

On This Page

When to Use
  • Immediate-effect binary settings — When toggling takes effect instantly without a Save button (dark mode, notification preferences, feature flags).
  • Settings panels grouped by category — Each switch controls an independent on/off preference.
  • Feature toggles in admin/developer UIs — Enable or disable system features with clear on/off feedback.
  • Inline activation in data tables — Small switch in a table's action column to enable/disable a row without opening a detail view.
When Not to Use
  • Form values submitted on Save — Use instead. Switches imply instant action; checkboxes represent form data.
  • Selecting multiple items from a list — Use for list selection.
  • Mutually exclusive choices (more than 2) — Use for options like "Never / Sometimes / Always".
  • Continuous value adjustment — Use for volume, brightness, or any range value.
Best Practices
  • Always provide a label — Never show a switch without adjacent text or at minimum an aria-label.
  • Label describes the setting, not the state — Use "Email notifications" not "Enabled". The switch itself communicates on/off.
  • Use loading state for async operations — Use loading={true} while awaiting an API response to prevent double-clicks.
  • Left-align labels in settings lists — Label on the left, switch on the right — consistent scan pattern.
  • Use large size on mobile — Large (52×28px) provides a more comfortable tap area on touch screens.
Patterns
  • Settings List — Stack switches vertically with labels left-aligned and switches right-aligned. Use --prim-space-5 gap between rows.
  • Feature Flag Panel — Large size with icon and description beneath the label. Show switch state prominently.
  • Table Row Toggle — Inline small switch in the last column. Pair with a Tooltip to clarify what is being toggled.
  • Permission Toggle — Pair with loading state and Toast feedback. Disable during async to prevent race conditions.
Anti-patterns
  • ❌ Switch without a label — An unlabelled switch is meaningless to all users.
    ✅ Fix: Always pair with visible text or an aria-label.
  • ❌ Switch for form-submitted values — "Accept terms" switch confuses users expecting explicit Save.
    ✅ Fix: Use a Checkbox for any value requiring a Save/Submit action.
  • ❌ No loading state on async toggles — Double-clicks cause inconsistent state.
    ✅ Fix: Always use loading={true} during async operations.
  • ❌ Labelling the state not the setting — "Enabled" is redundant; the switch shows on/off.
    ✅ Fix: Name the setting: "Email notifications", "Two-factor authentication".
