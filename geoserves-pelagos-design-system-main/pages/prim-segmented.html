Segmented Button

Overview

Segmented Buttons group 2–3 mutually exclusive options into a compact inline strip. A grey/50 pill track contains individual segments that become brand-blue when selected. Unlike radio buttons, all options are always visible — ideal for view switchers, filter groups, or mode selectors. Click any segment below to try it.

Anatomy

A Segmented Button group is a grey/50 track enclosing two or more segment buttons. Each segment may include a leading icon, label, count badge, and trailing icon — in any combination.

  1. Group track — Background: --prim-grey-50. Padding: 4px. Radius: --radius-md. Gap between segments: 2px.
  2. Segment (selected) — Background: --color-brand. Text: --prim-white. Radius: --radius-sm. Transition: 150ms ease.
  3. Icon — Optional 16×16px SVG. Inherits text colour (white on selected, --prim-grey-600 on default) via CSS currentColor.
  4. Label — Required. Font: --prim-font-weight-semibold / 14px. Colour driven by parent segment state.
  5. Badge — Optional count chip. 20px height, --radius-full. Background: --prim-grey-100 → 25% white (selected). Font: --prim-font-size-xs.

Semantic Pattern

The group uses role="group" + aria-label. Each segment is a <button role="option"> with aria-selected. Only the active segment has tabindex="0" (roving tabindex) — giving the whole group a single Tab stop.

Do / Don't
Do

  • Keep 2–3 segments. Pair icons with concise labels so every option is scannable at a glance.

Don't

  • Don't exceed 3 segments. For more options use a Dropdown or Tab bar instead.

Related Components
  • — Use when switching between full content panes rather than toggling a compact view mode.
  • — Use in forms when one choice must be submitted. Segmented Buttons are instant-apply.
  • — Use for a single on/off binary setting.
  • — Use when more than 3 options are available or screen space is limited.

Usage Patterns
JSX
// View-switcher — most common pattern
function DataViewSwitcher() {
  const [view, setView] = useState('grid');
  return (
    <div>
      <Segmented
        aria-label="Data view"
        value={view}
        onChange={setView}
        options={[
          { value: 'grid',  label: 'Grid',  icon: <GridIcon  size={16} /> },
          { value: 'list',  label: 'List',  icon: <ListIcon  size={16} /> },
          { value: 'table', label: 'Table', icon: <TableIcon size={16} /> },
        ]}
      />
      {view === 'grid'  && <GridPanel  />}
      {view === 'list'  && <ListPanel  />}
      {view === 'table' && <TablePanel />}
    </div>
  );
}

On This Page

When to Use
  • View mode switcher — Grid / List / Table, Map / Satellite. All options are always visible — no dropdown needed.
  • Time-range selector — Day / Week / Month in analytics dashboards. Compact alternative to a Dropdown when options are ≤ 3.
  • Filter strip with counts — Active / Archived tabs with badge counts above a data table.
  • Binary mode toggle — Light / Dark, Metric / Imperial. More discoverable than a Switch when both labels should be visible simultaneously.
When Not to Use
  • More than 3 options — Use . The strip becomes too wide.
  • Full-page navigation — Use . Segmented Buttons change a view inline; Tabs replace entire sections.
  • Form submissions — Use . Segmented Buttons are instant-apply; radios require submit.
  • Single on/off — Use for a binary setting.
Best Practices
  • Keep to 2–3 segments — Beyond 3 use a Dropdown or Tab bar.
  • Always start with one selected — Never render a group with nothing active; pre-select the most common option.
  • Use consistent content type — Don't mix icon-only and label-only in the same group.
  • Add aria-label on icon-only segments — Screen readers need text to identify the action.
  • Provide group aria-label — Describes what the control selects, e.g. "View mode".
Patterns
  • View Switcher — Top-right of a data panel. Connect onChange to conditionally render the view component.
  • Filter Strip — Pair with badge counts updated reactively as data changes.
  • Responsive Degradation — Below 640px: switch from label+icon to icon-only by conditionally omitting the label prop.
  • Toolbar Group — Use size="sm" icon-only segments in compact toolbars with 8px margins from neighbouring items.
Anti-patterns
  • ❌ 4+ segments — Overflow on small screens.
    ✅ Fix: Collapse to a Dropdown when options exceed 3.
  • ❌ No pre-selected option — Ambiguous state on load.
    ✅ Fix: Always set defaultValue or value to a valid option.
  • ❌ Icon-only without aria-label — Screen reader users hear only "button".
    ✅ Fix: Add aria-label="Grid view" to each icon-only segment.
  • ❌ Using for page routing — Clicking must not change the URL.
    ✅ Fix: Use Tabs or Nav for routing-level navigation.
