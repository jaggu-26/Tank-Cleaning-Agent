Search & Filter

The Search & Filter system is a toolbar-level pattern used across list and table views in GeoOne. It combines four tightly related primitives — Status Filter Chips, Search Field, Filter Button, and Filter Panel — to give users fast, intuitive control over large datasets.

1 · Status Filter Chips

Single-select chip group for filtering rows by status. One chip is always active. A vertical divider separates terminal states (Delivered, Draft) from actionable ones. Counts update dynamically to reflect filtered row totals.

On this page

All four Search & Filter primitives are available as React components (JSX) and as plain HTML/CSS. Import individually or use the SearchFilter composite for full toolbar functionality.

Installation
bash
import { SearchFilter } from '@pelagos/primitives/search-filter';
// or individual parts:
import { StatusFilterChips } from '@pelagos/primitives/search-filter';
import { SearchField }       from '@pelagos/primitives/search-filter';
import { FilterButton }      from '@pelagos/primitives/search-filter';
import { FilterPanel }       from '@pelagos/primitives/search-filter';
SearchFilter (composite)

Drop-in toolbar component that wires all four primitives together. Manages chip state, panel open/close, and filter count badge automatically.

JSX
import React, { useState } from 'react';
import { SearchFilter } from '@pelagos/primitives/search-filter';

// Status chips config
const STATUS_CHIPS = [
  { id: 'all',       label: 'All',                     count: 1677 },
  { id: 'pending',   label: 'Pending Credit Approval', count: 128  },
  { id: 'active',    label: 'Active',                  count: 89   },
  { id: 'finalise',  label: 'Finalise Qty',           count: 12   },
  { id: 'booked',    label: 'Booked',                 count: 215  },
  { id: 'delivered', label: 'Delivered',              count: 1202, dividerBefore: true },
  { id: 'draft',     label: 'Draft',                  count: 24   },
];

// Filter panel field definitions
const FILTER_FIELDS = [
  {
    id: 'substatus', label: 'Substatus', type: 'select',
    options: ['Pending Credit Approval', 'Credit Approved', 'Credit Rejected']
  },
  {
    id: 'tradeType', label: 'Trade Type', type: 'select',
    options: ['Spot', 'Contract', 'Term']
  },
  { id: 'assignee', label: 'Assignee', type: 'multi', placeholder: 'Search assignees…' },
  { id: 'vessel',   label: 'Vessel',   type: 'multi', placeholder: 'Search vessels…'   },
];

export function InquiryToolbar() {
  const [activeStatus, setActiveStatus] = useState('all');
  const [searchQuery, setSearchQuery]   = useState('');
  const [filters, setFilters]           = useState({});

  return (
    <SearchFilter
      chips={STATUS_CHIPS}
      activeChip={activeStatus}
      onChipChange={setActiveStatus}
      searchValue={searchQuery}
      onSearchChange={setSearchQuery}
      filterFields={FILTER_FIELDS}
      filterValues={filters}
      onFiltersApply={setFilters}
      searchPlaceholder="Search inquiries…"
    />
  );
}
StatusFilterChips
JSX
/**
 * StatusFilterChips
 * Props:
 *   chips         ChipItem[]   — array of { id, label, count, dividerBefore? }
 *   activeId      string       — currently selected chip id
 *   onChange      (id) => void — called on selection change
 */
export function StatusFilterChips({ chips, activeId, onChange }) {
  return (
    <div className="sf-chip-row" role="tablist" aria-label="Filter by status">
      {chips.map((chip) => (<React.Fragment key={chip.id}>
        {chip.dividerBefore && <div className="sf-chip-divider" aria-hidden="true" />}
        <button
          role="tab"
          aria-selected={chip.id === activeId}
          className={`sf-chip{chip.id === activeId ? ' is-active' : ''}`}
          onClick={() => onChange(chip.id)}
        >
          {chip.label} <span className="sf-chip-count">({chip.count})</span>
        </button>
      </React.Fragment>))}
    </div>
  );
}
SearchField
JSX
/**
 * SearchField
 * Props:
 *   value         string
 *   onChange      (value: string) => void
 *   onClear       () => void
 *   placeholder   string  (default: 'Search')
 *   width         number  (default: 210)
 */
export function SearchField({ value, onChange, onClear, placeholder = 'Search', width = 210 }) {
  return (
    <div className="sf-search-wrap">
      <svg className="sf-search-icon" viewBox="0 0 24 24" aria-hidden="true">
        <circle cx="11" cy="11" r="8"/>
        <line x1="21" y1="21" x2="16.65" y2="16.65"/>
      </svg>
      <input
        type="search"
        className={`sf-search-input{value ? ' has-value' : ''}`}
        value={value}
        onChange={(e) => onChange(e.target.value)}
        placeholder={placeholder}
        aria-label={placeholder}
        style={{ width }}
      />
      {value && (
        <button className="sf-search-clear" onClick={onClear} aria-label="Clear search">
          <svg width="8" height="8" viewBox="0 0 24 24"><path d="M18 6L6 18M6 6l12 12"/></svg>
        </button>
      )}
    </div>
  );
}
FilterButton & FilterPanel
JSX
/**
 * FilterButton
 * Props:
 *   isActive      boolean  — turns button brand-blue
 *   activeCount   number   — shows count badge when > 0
 *   onClick       () => void
 */
export function FilterButton({ isActive, activeCount, onClick }) {
  return (
    <button
      className={`sf-filter-btn{isActive ? ' is-active' : ''}`}
      onClick={onClick}
      aria-label="Open filters"
      aria-haspopup="dialog"
    >
      <svg viewBox="0 0 24 24">...filter icon...</svg>
      {isActive && activeCount > 0 && (
        <span className="sf-filter-badge" aria-label={`{activeCount} filters active`}>
          {activeCount}
        </span>
      )}
    </button>
  );
}

/**
 * FilterPanel
 * Props:
 *   isOpen       boolean
 *   onClose      () => void
 *   fields       FilterField[]  — { id, label, type:'select'|'multi', options?, placeholder? }
 *   values       Record<string, any>
 *   onApply      (values) => void
 *   onClear      () => void
 *   activeCount  number
 */
export function FilterPanel({ isOpen, onClose, fields, values, onApply, onClear, activeCount }) {
  const [draft, setDraft] = useState({...values});

  return (
    <>
      <div className={`sf-backdrop{isOpen ? ' is-open' : ''}`} onClick={onClose} />
      <div
        className={`sf-panel{isOpen ? ' is-open' : ''}`}
        role="dialog"
        aria-modal="true"
        aria-label="Filters"
        aria-hidden={!isOpen}
      >
        <div className="sf-panel-hdr">
          <div className="sf-panel-title">
            Filters
            {activeCount > 0 && <span className="sf-panel-badge">{activeCount}</span>}
          </div>
          <button className="sf-panel-close" onClick={onClose} aria-label="Close filters">...</button>
        </div>
        <div className="sf-panel-body">
          {fields.map(field => (
            <FilterGroup key={field.id} field={field} value={draft[field.id]}
              onChange={val => setDraft(d => ({...d, [field.id]: val}))} />
          ))}
        </div>
        <div className="sf-panel-footer">
          <button className="sf-btn-clear" onClick={() => { setDraft({}); onClear(); }}>Clear all</button>
          <button className="sf-btn-apply" onClick={() => { onApply(draft); onClose(); }}>Apply</button>
        </div>
      </div>
    </>
  );
}

When to use

Use the Search & Filter system when users need to navigate datasets of 20 or more rows. The chip group is most effective when there are 3–8 meaningful status categories. The Filter Panel is appropriate when there are 2 or more orthogonal filter dimensions beyond status.

Do

Use status chips when rows have a primary lifecycle status that users frequently filter by (e.g. Active, Pending, Delivered).

Keep chip labels short — 2–4 words. Place the "All" chip always first.

Show live counts in parentheses so users know how many items match before clicking.

Don't

Don't place more than 8 chips in a row — truncate overflow into a "+N more" chip or move extras to the filter panel.

Don't allow multi-select on status chips — they act as exclusive radio tabs, not checkboxes.

Don't put primary navigation actions (e.g. "New Inquiry") in the same row as filter chips — use separate toolbar zones.

Anatomy

The full toolbar is composed of three zones from left to right: the status chip group (primary filter), the search field (text query), and the filter button (panel trigger). The Filter Panel lives outside the normal document flow as an overlay.

1
Status Filter Chips

Single-select chip group. Exactly one chip is always selected. The active chip turns brand blue. Counts inside parentheses reflect the real row count for that status bucket.

2
Search Field

Free-text search over visible columns. The field subtly transitions to white with a brand-blue border ring on focus, signalling the active query. A clear (×) button appears when the value is non-empty.

3
Filter Button

A compact icon button that opens the Filter Panel. When any panel filter is active the button fills brand blue and a white badge shows the active filter count (max display: 9+).

4
Filter Panel

A 300px right-anchored overlay that houses structured filter controls. Changes are staged — edits don't take effect until the user clicks Apply. Clear All resets all panel fields at once.

Accessibility

Chip group: Use role="tablist" on the row and role="tab" + aria-selected on each chip. Support keyboard navigation with Arrow Left/Right to move between chips.

Search: Use type="search" for native browser clear affordance. Include aria-label matching the placeholder text. Debounce the onChange handler by 250–300ms to avoid re-rendering on each keystroke.

Filter Panel: Use role="dialog", aria-modal="true", and aria-label="Filters". Trap focus within the panel while open. Close on Escape. Move focus to the Filter Button when the panel closes.

Filter badge: Announce active filter count to screen readers with aria-label="{n} filters active" on the badge span.

Responsive behaviour

On viewports narrower than 768px the chip row scrolls horizontally (no wrapping). The search field drops to full-width below the chips. The Filter Panel always spans full viewport height minus a 24px inset at the top.

> 1024pxChips + Search + Filter Button all on one row
768–1024pxChips row wraps; Search + Filter Button stay right-aligned
< 768pxChips scroll horizontally; Search + Filter Button drop to second row at full width
