Email

The Email Panel is a multi-part compose surface used across GeoServe to send voyage summaries, SoF attachments, and operational notifications. It ships in two variants — Modal (floating, with backdrop) and Inline Panel (embedded directly in a page layout).

Variant 1 · Modal

The modal floats above the UI with a semi-transparent backdrop. Used when composition is a focused task that shouldn't interrupt the current page context. Max-width 800px, shadow-lg, border-radius 12px.

↑ Click to open the modal
Variant 2 · Inline Panel

The inline variant is embedded directly in the page layout — no overlay or backdrop. Matches the Back Office PC Summary screen: the compose surface occupies the right column of a split view. No modal shadow; bordered instead.

Anatomy

The email panel has five structural zones, each with a distinct role. The content area is the only scrollable zone — all other zones are sticky.

1
Header

Title "Compose Email" (Title1 B 20px Navy) + neutral close button (40×40px, icon only). In the inline variant the close button is omitted.

2
Email Info (To / Cc / Bcc / Subject)

100px label column (Title2 SB 18px grey) + value area. Recipients are rendered as chips with avatar, name, and a remove button. +Cc and +Bcc are neutral buttons (grey-10 bg, grey-200 border, 32px). Cc/Bcc rows expand on click.

3
Rich Text Toolbar

10 formatting buttons (Bold, Italic, Underline, Strikethrough, Link, Ordered List, Bullet List, Quote, Code, Table) + a vertical divider + an Attachment button. Each button is 32×32px, radius 4px, with hover state.

4
Content Area (scrollable)

A contenteditable div at 16px SB Navy. Flex-grow fills the remaining height. Supports drag-and-drop file upload (shows drag hint overlay).

5
Footer — Cancel + Send

Cancel: blue-10 background, marine border and text (Figma: btn-default outlined). Send / Submit: primary marine fill, white text. Both are 40px height, 16px h-padding.

Modal vs Inline Panel
Modal
Use when the email composition is a primary task that the user initiates deliberately — e.g. clicking "Send Nomination" or "Compose Email" in a table action. The backdrop prevents accidental interaction with the background.
Inline Panel
Use when the compose panel lives alongside context data — like the Back Office PC Summary screen where the user needs to see vessel/port details while composing. No overlay; occupies a side column.
Behaviour Notes
  • Cc/Bcc expansion — clicking + Cc or + Bcc appends a new row below the To row. The row is dismissible by removing all chips and blurring the input.
  • Recipient chips — typed email addresses or selected contacts become chips on Enter or comma. Chips show a 24×24 avatar with initials or a photo, the display name, and a remove (×) button. Invalid addresses show an error chip (red border).
  • Rich text toolbar — all 10 buttons (B, I, U, S, Link, OL, UL, Quote, Code, Table) use document.execCommand or a rich text editor lib. The active state (blue tint) reflects the selection context.
  • Drag-and-drop — dragging files onto the content area shows a "Drop files here" overlay. Dropped files appear in the attachments row as 186×40px chips with a file icon, truncated name, and a remove button.
  • Attachment button (paperclip, in the toolbar) opens the native file picker. Multiple files are supported.
Accessibility
  • The modal uses role="dialog", aria-modal="true", and aria-labelledby pointing to the title. Focus is trapped inside while open; Esc closes it.
  • Recipient chips have role="option" and aria-label="Remove [name]" on the close button.
  • Each toolbar button has a descriptive title attribute for tooltip and aria-label for screen readers.
  • The contenteditable editor has role="textbox", aria-multiline="true", and aria-label="Email body".
