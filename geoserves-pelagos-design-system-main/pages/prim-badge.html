Badge

Badges are compact, non-interactive indicators that communicate count, notification state, or product novelty. They attach to icons, avatars, or nav items without requiring any user action.

Types

Three distinct badge types, each with a fixed visual contract: Count badges show a number; Dot badges signal presence without a count; New badges announce first-time availability.

Interaction Behaviour

Badges have no interactive behaviour of their own. All visual feedback derives from the parent element.

No direct interaction

Set pointer-events: none. Clicks pass through to parent icon or button.

Count overflow

1–99: show exact number. 100+: show 99+. Never "1K". Never show 0 — hide the badge entirely.

Live updates

Update count value instantly on data change. Pair count badge with aria-live="polite" for screen readers.

NEW badge lifecycle

Show NEW badge only for features released in the past 30 days. Remove it after the user has visited the feature or after 30 days, whichever comes first.

Motion & Animation

Minimal motion. Entry animation for count badges only — dot and NEW badges appear instantly.

Accessibility

Badges must never be the sole carrier of information. The parent interactive element must always expose a complete accessible label.

Parent carries the label

The icon button wrapping a count badge must have aria-label="Notifications, 3 unread". The badge itself uses aria-hidden="true".

Dynamic count updates

Use a visually hidden aria-live="polite" region that mirrors the count for screen reader announcement on change.

Color contrast

Count-Neutral: #475569 on #e2e8f0 = 4.6:1 ✓. Count-Alert / dots: white on #dc2625 = 5.2:1 ✓. NEW badge white on gradient ≥ 4.5:1 ✓.

Focus exclusion

All badge types use pointer-events: none. Tab order skips them entirely.

Overview

Badge is a non-interactive indicator from @pelagos/components that attaches to icons, avatars, and nav items. It ships in three structural types — Count, Dot, and NEW — each with a fixed visual and semantic contract. All badge variants carry pointer-events: none and aria-hidden="true"; the parent element is responsible for accessible labelling.

The React component renders the correct markup based on the type prop. Count badges accept a count prop and render an overflow label when count > max.

The Angular component is a standalone component using ChangeDetectionStrategy.OnPush. Bind inputs via [type], [count], and [animate].

Quick Access

Badges communicate presence, count, or novelty. They are always attached to another element — never freestanding.

When to use
  • Count-Neutral: Unread items that don't require immediate action — messages, comments, updates.
  • Count-Alert: Urgent unread items that require attention — errors, critical alerts, action required.
  • Dot-Success: Active / online presence on avatars or status indicators.
  • Dot-Alert / Dot-Warning: Error or degraded state on system health icons, connection status.
  • NEW badge: Feature released in the last 30 days. Attach to nav items or feature labels.
When not to use
  • As a standalone label or status chip — badges always overlay a parent element.
  • As a button or interactive trigger — badges are pointer-events:none by design.
  • To show 0 — hide the badge entirely when count is zero.
  • Count-Alert for low-priority info — reserve red for genuinely urgent items only.
  • NEW badge after 30 days — stale badges erode trust in the "new" signal.
Content Hierarchy

Each badge type has a fixed content contract. Do not mix or repurpose them.

Accessibility Checklist
Icon/avatar parent carries complete aria-label including count (e.g. "3 unread notifications").
Dynamic count updates announced via a visually-hidden aria-live="polite" region.
All badge elements use aria-hidden="true" — the parent provides the semantic context.
All badge color pairs meet WCAG AA 4.5:1 minimum contrast.
Tab order skips all badge elements — pointer-events: none applied on all types.
prefers-reduced-motion removes count badge entry animation.
