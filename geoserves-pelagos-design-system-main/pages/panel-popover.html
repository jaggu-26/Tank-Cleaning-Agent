Popover

Overview

A Popover is a floating panel anchored to a trigger element — a button, icon, or any inline control. It acts as a shell: inner content is fully composable (menus, toggles, form fields, rich text). Popovers open on click or hover, close on outside click or Escape, and animate with a spring curve for a natural feel. Minimum width is 200 px.

On-click trigger

Hover trigger — useful for read-only contextual tips that don't require user interaction.

Anatomy

The popover is a shell — a positioned panel. All inner content is composable. The trigger element lives outside the panel and is connected only via JS.

  1. Trigger — any focusable element; receives aria-haspopup and aria-expanded.
  2. Panel shell — white background, 8 px radius, composite shadow, 200 px minimum width.
  3. Action item — 40 px min-height, 12 px horizontal padding, 12 px icon gap, 14 px Gilroy.
  4. Icon slot — 24 × 24 px box; optional but recommended for scanability.
  5. Divider — 1 px line, 4 px vertical margin, 12 px horizontal inset.

Animation

Spring easing — cubic-bezier(0.16, 1, 0.3, 1) — produces a natural snap-open feel. The panel scales from 0.95 → 1.0 and translates 4 px toward the trigger on enter. Exit is a short reverse (180 ms) so it doesn't compete with the next interaction.

Overview

Popover wraps any trigger element and floats a composable panel. Use PopoverItem, PopoverDivider, and PopoverToggleRow as content sub-components.

Use the .gs-pop-wrap wrapper with .gs-popover panel and call gsPopoverToggle() or gsPopoverOpen() from the global JS API.

Full Example
JSX
import { useState } from 'react';
import {
  Popover, PopoverItem, PopoverDivider, PopoverToggleRow,
} from '@pelagos/components/panels/popover';
import { Toggle } from '@pelagos/components/primitives/toggle';

export function ClaimActions({ claim, onEdit, onDelete }) {
  const [active, setActive] = useState(claim.active);

  return (
    <Popover
      placement="bottom"
      trigger="click"
      content={
        <>
          <PopoverItem
            icon={<EditIcon />}
            label="Edit Details"
            onClick={onEdit}
          />
          <PopoverDivider />
          <PopoverToggleRow label="Active Counterparty">
            <Toggle checked={active} onChange={setActive} />
          </PopoverToggleRow>
          <PopoverDivider />
          <PopoverItem
            icon={<TrashIcon />}
            label="Delete"
            danger
            onClick={onDelete}
          />
        </>
      }
    >
      <button className="gs-btn gs-btn-secondary gs-btn-sm"
        aria-label={`Actions for ${claim.id}`}>
        <DotsIcon />
      </button>
    </Popover>
  );
}

When to Use
  • Secondary actions on a row or card — an overflow menu (⋯) avoids cluttering the primary UI with rarely-used operations.
  • Status or assignment pickers — inline dropdowns that feel lighter than a full modal (e.g., change claim status, assign user).
  • Quick toggles tied to a record — the "Active Counterparty" toggle-row pattern keeps context without navigation.
  • Contextual info on hover — a read-only panel that expands on hover for glossary terms, field help, or vessel summaries.
  • Lightweight confirmations — small panels with Cancel + Confirm buttons for low-stakes destructive actions.
When Not to Use
  • Complex forms or multi-step flows — use or instead. Popovers have no scroll containment guarantee.
  • Brief single-line hints — use instead. Tooltips have no interactive content and lighter markup.
  • Primary navigation — popovers are transient overlays; persistent navigation belongs in the side-nav or tab bar.
  • Error or success feedback — use or inline validation instead. Popovers require a trigger; feedback should be unprompted.
Best Practices
  • One popover open at a time — the global JS handler closes all others when a new one opens. Never open two popovers simultaneously.
  • Minimum 200 px width — per Figma spec. Shorter panels look cramped and break at typical viewport zoom levels.
  • Keep hover trigger content read-only — users on touch devices cannot hover. Reserve interactive items (buttons, toggles) for click triggers.
  • Limit item count to 7 ± 2 — long menus lose scannability. Group related items with dividers and consider a search-inside pattern beyond 10 items.
  • Always provide a dismiss path — click outside, Escape key, or an explicit Cancel button. Never trap focus in a hover panel.
  • Use bottom-start as the default placement — left-aligned panels align with the button's left edge, which is the most natural reading direction for LTR interfaces.
Patterns
  • Row overflow menu — a ⋯ icon button at the end of a table row opens a context menu (Edit, Clone, Delete). Use trigger="click" and placement="bottom-end".
  • Record action panel — a labelled "Actions" button opens a panel with grouped items separated by a divider. Primary actions first, destructive (red) items last.
  • Status picker — a Badge or Chip triggers a panel of selectable status options. Each option has a colour dot, label, and a checkmark when active.
  • Toggle row — a settings action that includes a toggle (e.g. "Active Counterparty") uses PopoverToggleRow below a divider, keeping the toggle reachable without a full settings page.
  • Info hover card — a small info icon (ⓘ) shows a rich tooltip card on hover with a vessel summary, user card, or glossary definition. Use trigger="hover".
Anti-patterns
  • ❌ Nesting popovers — a popover item that opens another popover creates confusing z-index stacking and unpredictable dismiss behaviour.
    ✅ Fix: Flatten the hierarchy or open a Modal for deeper options.
  • ❌ Hover trigger for actionable content — buttons and toggles inside a hover panel are unreachable on touch devices and fail WCAG 2.1 §1.4.13.
    ✅ Fix: Switch to trigger="click" whenever the panel contains any interactive element.
  • ❌ Missing aria-haspopup / aria-expanded — screen readers won't announce the trigger correctly.
    ✅ Fix: Add both attributes to every trigger; toggle aria-expanded in sync with panel state.
  • ❌ Inline min-width smaller than 200 px — items wrap unexpectedly and the panel looks broken at zoom levels above 100%.
    ✅ Fix: Never override --pop-min-w below 200 px.
