# How to Add a New Component Page — Pelagos Design System

## Overview

Adding a component page requires changes to **3 files** and creation of **1 new file**:

1. `pages/{prefix}-{name}.html` — new component page (create)
2. `script.js` — register page in PAGES map + add tab-switch function
3. `index.html` — no changes needed (nav is built dynamically by script.js)

Nav tree is generated by `buildNav()` in `script.js`. Add the page to the `PAGES` map and the nav tree data structure — both described below.

---

## Step 1 — Choose a Prefix

Pick a short, unique 2–4 letter prefix derived from the component name.
This prefix is used for ALL IDs and scoped class names.

| Component     | Prefix |
|---------------|--------|
| Button        | `btn`  |
| Radio Button  | `rb`   |
| Checkbox      | `cb`   |
| Chips         | `chip` |
| Badge         | `bdg`  |
| Text Field    | `tf`   |
| Modal         | `mod`  |
| Tooltip       | `tt`   |

**Rule:** prefix must not already exist in `script.js`. Grep to check:
```
grep -n "switch{Name}Tab\|'{prefix}-tab" script.js
```

---

## Step 2 — Add Tab-Switch Function to script.js

Find the `// ── {last component} ───` block near the bottom of `script.js` and append:

```javascript
// ── {Component Name} tab switching ───────────────────────────
function switch{Name}Tab(tab) {
  var page = document.getElementById('page-content');
  if (!page) return;
  page.querySelectorAll('.{prefix}-tab-btn').forEach(function(b) { b.classList.remove('active'); });
  page.querySelectorAll('.{prefix}-tab-pane').forEach(function(p) { p.classList.remove('active'); });
  var pane = document.getElementById('{prefix}-tab-' + tab);
  if (pane) pane.classList.add('active');
  var btn = page.querySelector('.{prefix}-tab-btn[data-tab="' + tab + '"]');
  if (btn) btn.classList.add('active');
}
```

Replace `{Name}` with PascalCase component name (e.g., `RadioButton`, `Tooltip`).
Replace `{prefix}` with the prefix chosen in Step 1.

---

## Step 3 — Register Page in PAGES Map (script.js)

Find `const PAGES = {` near line 134 of `script.js`.
Add an entry under the correct category group (Primitives / Panels / Views / Navigations / Forms):

```javascript
'{prefix}-{name}': { label: '{Component Name}', nav: 'nav-{prefix}-{name}', parent: '{Category}' },
```

Example (adding Tooltip to Primitives):
```javascript
'prim-tooltip': { label: 'Tooltip', nav: 'nav-prim-tooltip', parent: 'Primitives' },
```

**Categories available:** `Foundations`, `Primitives`, `Panels`, `Views`, `Navigations`, `Forms`

---

## Step 4 — Add Nav Item to Nav Tree (script.js)

Find the `NAV_TREE` or `buildNav()` function in `script.js`.
Add a child entry under the appropriate group.

The nav renders items via `data-navigate` attributes. The `nav` value in the PAGES map (e.g., `nav-prim-tooltip`) must match the `id` of the rendered nav item. The `buildNav()` function handles this automatically from the tree data — just add:

```javascript
{ id: 'prim-{name}', label: '{Component Name}' },
```

under the appropriate group array (Primitives, Panels, etc.).

---

## Step 5 — Create the Page File

File path: `pages/{prefix}-{name}.html`

The file is injected into `<div id="page-content">` by `navigate()` in `script.js`.
**No `<html>`, `<head>`, `<body>` tags.** Pure component markup only.
**No `<script>` tags.** All JS lives in `script.js`.

---

## Page Structure (required shell)

```html
<!-- ═══════════════════════════════════════════════════════════════
     {COMPONENT NAME} — Pelagos Design System
     ═══════════════════════════════════════════════════════════════ -->

<!-- BANNER -->
<div class="page-header">
  <h1 class="ds-hero-title">{Component Name}</h1>
</div>

<!-- TAB BAR -->
<div class="btn-tab-bar">
  <button class="btn-tab-btn {prefix}-tab-btn active" data-tab="design" onclick="switch{Name}Tab('design')">Design</button>
  <button class="btn-tab-btn {prefix}-tab-btn"        data-tab="code"   onclick="switch{Name}Tab('code')">Code</button>
  <button class="btn-tab-btn {prefix}-tab-btn"        data-tab="usage"  onclick="switch{Name}Tab('usage')">Usage</button>
</div>

<!-- DESIGN TAB -->
<div id="{prefix}-tab-design" class="btn-tab-pane {prefix}-tab-pane active">
  <div class="code-tab-layout">
    <div class="code-tab-main">
      <!-- sections go here -->
    </div>
    <div class="code-tab-qnav">
      <!-- design quick-nav goes here -->
    </div>
  </div>
</div>

<!-- CODE TAB -->
<div id="{prefix}-tab-code" class="btn-tab-pane {prefix}-tab-pane">
  <div class="code-tab-layout">
    <div class="code-tab-main">
      <!-- framework switcher + code sections go here -->
    </div>
    <div class="code-tab-qnav">
      <!-- code quick-nav goes here -->
    </div>
  </div>
</div>

<!-- USAGE TAB -->
<div id="{prefix}-tab-usage" class="btn-tab-pane {prefix}-tab-pane">
  <div class="code-tab-layout">
    <div class="code-tab-main">
      <!-- usage sections go here -->
    </div>
    <div class="code-tab-qnav">
      <!-- usage quick-nav goes here -->
    </div>
  </div>
</div>
```

**Critical class rules:**
- Tab buttons: BOTH `btn-tab-btn` AND `{prefix}-tab-btn` on every button
- Tab panes: BOTH `btn-tab-pane` AND `{prefix}-tab-pane` on every pane
- Design tab pane + first tab button get `active` class by default

## Section Card Pattern (used in ALL tabs)

Every section is wrapped in this card shell:

```html
<div id="{prefix}-{tab-letter}-{slug}" class="btn-family-card">
  <div class="btn-family-title">{Section Title}</div>
  <p class="btn-family-desc">{Optional one-line description}</p>
  <!-- section content -->
</div>
```

**ID naming:**
- Design sections: `{prefix}-s-{slug}` (e.g., `rb-s-overview`)
- Code sections: `{prefix}-c-{slug}` (e.g., `rb-c-install`)
- Usage sections: `{prefix}-u-{slug}` (e.g., `rb-u-when`)

**Rules:**
- Title element is always `<div class="btn-family-title">` — never `<h2>` or other
- Do NOT use `<section>`, `<h2>`, `ds-section`, or `ds-section-title` — those are old classes

## Live Preview Rules

**Always** add `style="pointer-events:none;"` to the wrapper div of any live component demo.
This prevents accidental interaction inside documentation previews.

```html
<!-- correct -->
<div style="pointer-events:none;">
  <button class="gs-btn gs-btn--primary">Click me</button>
</div>

<!-- wrong — interactive inside preview -->
<button class="gs-btn gs-btn--primary">Click me</button>
```

## Global Functions Available (do not redefine)

| Function | Purpose |
|----------|---------|

| `scrollToSection(id)` | Smooth-scrolls to a section by ID |

| `navigate(pageId)` | Navigates to another page by PAGES key |

## Common Mistakes to Avoid

| Wrong | Correct |
|-------|---------|
| `<section class="ds-section">` | `<div class="btn-family-card">` |
| `<h2 class="ds-section-title">` | `<div class="btn-family-title">` |
| `<p class="ds-section-desc">` | `<p class="btn-family-desc">` |
| `<div class="ds-tab-bar">` | `<div class="btn-tab-bar">` |
| `<button class="chip-tab-btn">` (one class) | `<button class="btn-tab-btn chip-tab-btn">` (both) |
| `<div class="chip-tab-pane">` (one class) | `<div class="btn-tab-pane chip-tab-pane">` (both) |
| `<button class="fw-btn">` | `<button class="fw-toggle-bar-btn">` |
| Live component without `pointer-events:none` | Wrapper div always has `style="pointer-events:none;"` |
| Inline `<script>` in the HTML file | All JS in `script.js` only |
